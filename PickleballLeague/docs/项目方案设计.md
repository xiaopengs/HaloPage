# 项目方案设计

## 1. 方案概述

本次重构放弃此前“深色玻璃拟态仪表盘”的视觉包袱，改用**赛事编辑部 × 现场记分板**的视觉系统。页面像一份不断刷新的赛事日报：暖白纸张作为信息底板，黑色大字负责比分与人名，网球场荧光绿负责“正在发生”，砖红色只用于胜负和警示。视觉以强烈排版、细网格、计分带和少量像素人物徽章建立识别，而不是依赖阴影、发光或大面积渐变。

> 设计原则：每个视觉元素都必须回答一个问题——它是否让组织者更快地知道“下一步该录哪场、当前谁领先、规则如何计算”？

## 2. 信息架构

| 一级页面 | 核心信息 | 主要操作 |
| --- | --- | --- |
| 赛事首页 | 赛季状态、当前/下一场、规则、六人阵容、榜首 | 跳转至录分、赛程、榜单。 |
| 赛程 | 5 轮 × 3 场的完整对局 | 点击任意卡片进入对应录分。 |
| 录分 | 当前对局、双方人物、分数输入、校验提示 | 保存、覆盖或清除当前赛果。 |
| 榜单 | 积分、胜负、得失分、净胜分及排序规则 | 查看实时名次。 |
| 颁奖 | 完赛状态、冠军、亚军、季军 | 在赛季结束后展示最终结果。 |

## 3. 视觉系统

| 要素 | 决策 | 目的 |
| --- | --- | --- |
| 背景 | 暖灰白 `#F4F1E8` 与纸张细纹 | 提升长时间查看数据的舒适度，并区别此前深色视觉。 |
| 主文字 | 墨黑 `#151515`，标题采用压缩粗体 | 建立比分板般直接、高对比的信息层级。 |
| 激活色 | 场地绿 `#C7FF3E` | 只标识正在进行、主操作、领先者和关键数字。 |
| 警示/胜负 | 砖红 `#E64B32` | 用于无效比分、失败提示和少量对比。 |
| 结构 | 12 列桌面网格、2 列移动网格、细线分割 | 让赛程、规则、榜单都能快速扫描。 |
| 人物 | 一张统一像素人物图切分出的六个独立头像 | 让固定阵容具备统一识别，同时保留清晰的姓名文本。 |

## 4. 前端实现与数据模型

页面维持纯 HTML、CSS、JavaScript 和 `localStorage`。固定选手数据包含 `id`、姓名、性别、头像 URL；赛程按圆圈法在浏览器生成；比分按 `matchId → {a, b}` 保存。统计模块作为唯一计算源，输出场次、胜、负、积分、得分、失分和净胜分；首页、榜单和领奖台都只消费这个统计结果，避免多处计算产生不一致。

## 5. 移动端方案

移动端不是桌面端的缩放版本。顶部使用可横向滚动的紧凑导航；首页首屏先展示下一场与主操作；规则卡变为横向可滑动的四张信息带；人物改为两列网格；赛程按轮次堆叠；录分时两位选手的分数输入保持同屏、单手可点；榜单保留“排名、选手、积分、净胜分”四列，其他字段展开后查看。最小触控目标为 44px，关键按钮固定在拇指可达的页面底部区域。

## 6. 验收依据

验收包括：固定姓名与性别准确；每位选手 5 场、总计 15 场；`11:10` 与 `10:8` 被拒绝，`11:9` 和 `12:10` 可保存；保存后榜单即时更新；15 场完成后冠军与亚军正确显示；在 375px 宽屏幕下不存在横向页面溢出，录分控件、赛程卡和榜单关键信息均可读可点。
