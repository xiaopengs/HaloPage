关键判断

Manus 的通用性来自哪里？

官方虚拟机具备图灵完备的执行能力，所以任务不被固定工作流完全限制。
官方Skills 是文件系统中的可复用工作流；MCP 更偏向外部数据连接层。
推断Orchestrator、模型路由和权限策略应是服务端控制平面，但官方未公开其内部拆分。

1. 控制面：把自然语言变成持续决策

用户任务先进入 Task / Project 语义容器，再由控制逻辑把模型调用、工具执行、等待事件和恢复串起来。公开资料没有给出内部服务名，因此图中 Orchestrator 与 Model Gateway 使用虚线，表示合理的系统分层推断。

2. 执行面：云电脑是“手”

Sandbox 不是普通代码运行器，而是具备网络、文件系统、浏览器和软件工具的隔离云 VM。它让 Agent 能执行脚本、访问网页、生成网站和持续产出文件。

3. 上下文面：文件系统是外置记忆

Manus 官方明确提出用文件系统承载长期上下文：网页内容可以从当前上下文移出，但保留 URL；文档可以从上下文省略，但保留路径。todo.md 则把全局计划重新写回注意力末端。

4. 扩展面：Skills、Connectors、并行 Agent

Skills 提供可复用操作手册，Connectors 连接外部数据，Wide Research 通过并行 VM 和通用子 Agent 扩大计算规模。三者分别对应知识复用、数据接入和横向扩展。

任务运行时序

  1. 接收：用户/API 创建任务，任务上下文和附件进入 Task / Project。
  2. 规划：Agent Loop 读取目标、已有文件和可用工具，选择下一步动作。
  3. 执行：Tool Router 把动作分派给 Shell、Browser、Connector 或 Sandbox 内的程序。
  4. 观察：工具结果、错误和产物追加回上下文；错误不应被简单抹掉，因为它是下一轮决策的证据。
  5. 外置：长内容写入文件，todo.md 复述计划；上下文保持 append-only 以利于缓存。
  6. 交付：文件、报告、网站等 Artifact 输出给用户，API 任务则可通过状态事件 / Webhook 接收完成通知。

共同点：都是“观察—决策—行动”循环

ReAct 的经典循环是 Thought → Action → Observation。模型通过行动访问外部环境，再根据观察调整后续计划。Manus 的 Agent Loop 保留了这一认知骨架，但把它放进了更完整的运行时：上下文、工具状态、文件系统和云端执行环境共同参与下一步决策。

关系判断：Manus 不是 ReAct 的对立方案，更像是把 ReAct-like loop 工程化为可长时间运行的 Agent Harness。

核心差别：范式 vs. 生产系统

ReAct 主要回答“模型如何边推理边行动”；Manus 还要回答“如何让这个循环低成本、可恢复、可扩展地运行”。因此 Manus 把 KV-cache、工具约束、外部化记忆、错误轨迹和并行 Sandbox 纳入核心设计。

官方Manus 公开文章明确讨论 append-only 上下文、KV-cache、工具可用性状态机和文件系统上下文。
边界Manus 内部是否直接采用某个 ReAct prompt 模板，官方没有公开；这里比较的是可观察的循环结构与系统机制。

ReAct：重点在显式推理轨迹

ReActReasoning trace：通常显式产生 Thought，用于拆解目标、跟踪进度、处理异常。
ReActAction space：一般由特定任务环境定义，规模相对有限。
ReActMemory：主要依赖轨迹上下文维持工作记忆。
ReActEnvironment：可以是 Wikipedia API、网页环境、文本游戏或模拟器。

Manus：重点在可持续执行

ManusState：用 todo.md、工作文件、产物路径和工具记录外置部分任务状态。
ManusTools：保持工具定义稳定，使用状态机和解码约束屏蔽当前不可用动作。
ManusRuntime：在隔离云 VM 中执行 Shell、浏览器、文件操作和软件工具。
ManusScale：通过 Wide Research 并行启动通用子 Agent 和独立 Sandbox。
一句话：ReAct 让模型学会“边想边做”；Manus 让这种“边想边做”成为一个能处理长任务、真实文件、失败恢复、工具扩展和并行执行的生产系统。

官方明确

  • 每个任务分配隔离的 Manus Sandbox 云虚拟机。
  • Sandbox 具备网络、文件系统、浏览器和软件工具。
  • Agent Loop 采用工具调用、追加上下文、文件系统上下文和工具可用性状态机等设计。
  • Skills 以文件系统资源形式渐进披露；Connectors 与 Skills 分工互补。
  • Wide Research 使用并行处理和通用子 Agent。
  • 可使用 My Browser 连接本地已登录浏览器，但需用户授权。

未公开 / 不应臆测

  • 内部微服务数量、服务边界、数据库类型和队列实现。

  • 沙箱底层虚拟化技术、网络隔离细节和资源调度算法。
  • 权限、审计、密钥托管的完整内部实现。
  • Wide Research 的精确拓扑、聚合协议和成本控制算法。
