01 / OVERVIEW

方案总览：我们要做什么

一句话概括：把一段"人物转身"的视频当作可拖动的胶片，鼠标左右移动 = 用手搓动胶片，从而实现"鼠标往哪移，人物往哪看"的丝滑交互。

效果是什么样的

页面背景是一幅山巅侠客的画面。它不自动播放——视频完全静止，时间轴由你的鼠标接管：鼠标向左滑，人物上半身、头部和眼神缓缓转向画面左侧；向右滑，则转向右侧。天空、云彩、机位、站位全程不变。

为什么不能直接"播放"

普通视频是"放电影"：时间轴自己往前走。而我们要的是"拉胶片"：时间轴完全听鼠标指挥，鼠标不动画面就静止。所以技术上有三个关键词：

核心 1

不自动播放
视频 muted + playsInline + preload="auto"，并显式 pause()。

核心 2

鼠标映射时间轴
鼠标 X 坐标 ÷ 屏幕宽度 = 视频进度百分比。

核心 3

平滑 seek
用插值 + 队列防抖动，杜绝机械感和卡顿。

为什么要"等 seeked"浏览器的 seek 是异步的，一帧 seek 没完成就塞下一个，会排队拥堵（叫 seek-flooding），画面反而卡。所以我们一次只发一个 seek，完成后再追最新目标——就像等电梯，而不是狂按按钮。

04 / TRANSCODE

视频规格与转码

AI 生成的原始视频不能直接上线——编码格式、关键帧密度、体积都不对。这一步用一条 FFmpeg 命令全部搞定。

目标规格一览

项目推荐值说明
分辨率1920×1080（16:9）桌面主流比例；人物放右侧 2/3 安全区
编码H.264 (libx264)全浏览器通吃；不要用 HEVC/H.265，Chrome/Firefox 多数放不了
像素格式yuv420p浏览器兼容性最好的色彩格式
关键帧间隔-g 5（每 5 帧一个）本方案的生命线，详见下方坑位说明
B 帧-bf 0（关闭）避免双向预测帧导致的 seek 延迟
音频-an（剔除）静音视频不需要音轨，省体积
moov 前置+faststart元数据放文件头，边下边播
质量-crf 15~19数字越小越清晰体积越大；背景视频 18 左右即可

一条命令完成转码

# 把 input.mp4 转成本方案可用的网页视频
ffmpeg -y -i input.mp4 \
  -c:v libx264 -pix_fmt yuv420p \
  -crf 18 -preset medium \
  -g 5 -keyint_min 5 -sc_threshold 0 -bf 0 \
  -movflags +faststart \
  -an \
  output.mp4

关键帧：本方案最大的隐形坑

视频 seek（跳转）时，浏览器只能精确落到关键帧，普通帧需要从最近的关键帧逐帧推算。AI 生成的视频往往整个文件只有 1 个关键帧——这意味着每次 seek 都要从第 0 帧算到目标帧，鼠标一动就卡成 PPT。

图 4-1 · 关键帧密度对比：-g 5 是丝滑 seek 的前提
!
验证方法转码后用 ffprobe -select_streams v -show_entries frame=pict_type -of csv output.mp4 | grep I | wc -l 数一下 I 帧（关键帧）数量，5 秒视频应有 30 个以上；如果只有 1~2 个，说明参数没生效。
05 / CODE

加载与交互代码

本页给出完整可运行的核心代码，逐段讲解。直接复制即可用，小白也能看懂每一行在干嘛。

第一步：HTML 视频标签

<video id="heroVideo"
       muted            // 静音（自动播放策略 & 用户体验双重要求）
       playsinline      // iOS Safari 必须，否则强制全屏播放
       preload="auto"   // 提前缓冲，鼠标一动就能响应
       src="turn.mp4">
</video>
// 注意：不写 autoplay！我们不需要它播放。

第二步：鼠标坐标 → 目标时间

let targetTime = 0;   // 鼠标想去的时间点
let smoothTime = 0;   // 平滑后的实际渲染时间

window.addEventListener("mousemove", (e) => {
  if (!video.duration) return;
  // 鼠标 X 占比 0~1，映射到整条时间轴；方向反了就写 1 - ratio
  const ratio = 1 - e.clientX / window.innerWidth;
  targetTime = Math.max(0, Math.min(video.duration, ratio * video.duration));
}, { passive: true });
✓
方向反了怎么办如果实际效果是"鼠标往左人却往右"，把 ratio 改成 1 - ratio 即可——这取决于你的视频是"从左往右转"还是"从右往左转"拍的。

第三步：平滑引擎（灵魂代码）

let seeking = false;
const SEEK_EPS = 1 / 48;  // 小于半帧不动，防空转

function tick() {
  // ① 指数平滑：每帧向目标靠近 14%，快而不冲，无机械感
  smoothTime += (targetTime - smoothTime) * 0.14;

  // ② 串行 seek：上一个没完成就不发下一个
  if (!seeking && Math.abs(smoothTime - video.currentTime) > SEEK_EPS) {
    seeking = true;
    video.currentTime = smoothTime;
  }
  requestAnimationFrame(tick);
}

// ③ seek 完成放行；期间目标变了，下一帧自动追赶最新值
video.addEventListener("seeked", () => seeking = false);
requestAnimationFrame(tick);

第四步：加载进度条

// 监听真实缓冲进度
video.addEventListener("progress", () => {
  if (video.buffered.length && video.duration) {
    real = video.buffered.end(video.buffered.length - 1) / video.duration;
  }
});
// 展示进度平滑追赶真实进度，到 100% 隐藏加载层
shown += (real - shown) * 0.12;
barFill.style.width = Math.round(shown * 100) + "%";

为什么这样就"丝滑"了

手段解决的问题
rAF 插值 0.14鼠标事件是离散的，直接赋值会一格一格跳；插值让时间像水一样流过去
串行 seek 队列防止 seek 堆积（seek-flooding），浏览器不会卡顿假死
SEEK_EPS 半帧阈值目标已到位就不再发 seek，CPU 解码器不空转
密集关键帧（第 4 页）每次 seek 最多推算 4 帧，毫秒级完成
06 / RESPONSIVE

多端适配方案

同一个视频要在宽屏显示器、笔记本、平板、手机上都好看，核心矛盾只有一个：窗口比例 ≠ 视频比例。

桌面端：cover 铺满 + 安全区构图

桌面用 object-fit: cover 让视频铺满全屏，多余部分裁掉。裁切不可避免，所以构图时就要留安全区：

图 6-1 · 安全区示意：重要内容放中央，边缘留给裁切

移动端：三个必须处理的差异

差异对策
没有鼠标改用 touchmove / 陀螺仪 deviceorientation，或退化为"轻点屏幕左右半区转身"
iOS 强制全屏必须写 playsinline + webkit-playsinline，否则视频跳出页面全屏播放
流量与性能移动端提供 720p 小体积版本，用 <source media> 或 JS 按屏宽切换

比例兜底：不想裁切时

如果画面一像素都不想被裁（例如客户提供的成品图），可以放弃 cover，改用原比例完整呈现 + 模糊延展填充：中间是严格原始比例的画面，四周空隙用同一张图的放大模糊版填满，视觉连续无黑边。本方案的作品集主页就预留了这种写法。

✓
怎么选追求沉浸感选 cover 铺满（推荐）；追求构图完整选原比例 + 模糊延展。两者不要混用。
07 / PITFALLS

踩坑指南

以下 8 个坑全部是真实项目中踩过的，按"踩坑概率"从高到低排列。每个坑都给出症状、原因和解药。

1
鼠标一动就卡成 PPT（概率 ★★★★★）症状：鼠标滑动时画面 1 秒才动一下。原因：视频只有 1 个关键帧，每次 seek 都从头推算。解药：转码加 -g 5 -keyint_min 5 -sc_threshold 0 -bf 0（见第 4 页）。
2
视频在浏览器里黑屏/无法解码（★★★★☆）症状：本地能播，网页里黑屏。原因：AI 工具常导出 HEVC(H.265)，Chrome/Firefox 多数设备不支持。解药：必须转码为 H.264 + yuv420p。
3
转身方向和鼠标相反（★★★★☆）症状：鼠标往左，人往右看。原因：视频拍摄方向与映射方向不一致。解药：把 ratio 换成 1 - ratio，一行搞定，不用重新生成视频。
4
画面一顿一顿、有机械感（★★★★☆）症状：人物跟随很"硬"，像机器人。原因：直接把鼠标事件映射到 currentTime，事件是离散的。解药：加 rAF 指数插值（系数 0.1~0.15），让时间"流"过去而不是"跳"过去。
5
快速甩鼠标后页面假死（★★★☆☆）症状：疯狂晃动鼠标几秒后页面卡住。原因：seek-flooding——seek 请求堆积。解药：串行 seek 队列 + seeked 回调放行 + 120ms 兜底解锁。
6
iPhone 上视频突然全屏（★★★☆☆）症状：iOS Safari 里视频跳出页面全屏播放。原因：缺少 playsinline。解药：同时写 playsinline 和 webkit-playsinline。
7
背景云/草在来回倒放（★★★☆☆）症状：转身正常，但云和草随鼠标来回倒放，很诡异。原因：生成视频时背景有运动元素。解药：只能重新生成——提示词里强调 frozen background（见第 3 页）。
8
AI 超分提清晰度失败（★★☆☆☆）症状：想用 Real-ESRGAN 逐帧高清化，跑不动。原因：无 GPU 环境跑 153 帧要几十分钟甚至装不上依赖。解药：优先用 FFmpeg 的 scale=1920:1080:flags=lanczos 高质量缩放 + 低 CRF；真要 AI 超分，找有 GPU 的机器离线跑。
✓
排查口诀卡 → 查关键帧；黑 → 查编码；反 → 改 ratio；硬 → 加插值；死 → 查队列；全屏 → 加 playsinline。
08 / TUTORIAL

小白实操教程：30 分钟从零到上线

不需要任何编程基础，跟着步骤一步步来。所有命令和代码在第 3~5 页都有成品可复制。

生成转身视频

打开你常用的 AI 视频工具（可灵 / Runway / Pika 等），粘贴第 3 页的提示词模板，生成一段 4~6 秒、16:9 的"人物匀速转身"视频。生成 2~3 条，挑背景最干净、转身最匀速的一条。

安装 FFmpeg

Windows：官网下载解压，把 bin 目录加入环境变量；Mac：brew install ffmpeg；Linux：apt install ffmpeg。装好后命令行输入 ffmpeg -version 有输出即成功。

转码视频

把视频重命名为 input.mp4，打开命令行进入该目录，粘贴第 4 页的转码命令，得到 output.mp4。用 ffprobe 验证关键帧数量（第 4 页底部有命令）。

搭建页面骨架

新建 index.html，写入视频标签（第 5 页第一步），视频文件放在同目录的 assets 文件夹。用浏览器打开，能看到第一帧画面即成功。

接入鼠标交互

把第 5 页第二、三步的 JS 代码粘进 <script> 标签。刷新页面，左右移动鼠标——人物应该开始转身了。方向反了就改 ratio（第 5 页有说明）。

加上加载进度条

粘入第 5 页第四步代码，配一条 CSS 进度条样式。这样首次访问时用户看到加载进度，而不是黑屏等待。

三端自测

按第 6、7 页 checklist 过一遍：Chrome/Safari/Edge 各开一次；手机扫码打开；把窗口拉宽拉窄看裁切；疯狂甩鼠标 10 秒看是否假死。全部通过即可部署。

✓
完成标准鼠标轻移人物缓缓转头、急甩不卡、方向一致、加载有进度、手机不全屏——五条全中，恭喜毕业。
