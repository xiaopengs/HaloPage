# 交互设计说明

## 1. 交互语气

交互应像裁判记分，而不是像填写表格：**短、准、可撤销**。默认界面只显示当前需要的信息；完成一项操作后，立刻把下一项带到用户面前。动效仅用于状态切换和保存确认，时长控制在 160–240ms，并尊重系统的减少动态设置。

## 2. 关键流程

| 流程 | 触发 | 系统反馈 | 结束状态 |
| --- | --- | --- | --- |
| 从首页开始录分 | 点击“录入下一场” | 直接定位到首个未完成对局 | 双方分数输入框获得视觉强调。 |
| 选择其他对局 | 点击赛程卡或对局列表 | 卡片变为荧光绿描边，录分区切换人物 | 显示该场已有分数或空态。 |
| 保存合法比分 | 输入不同分数，胜方 ≥11 且差 ≥2 | 保存按钮短暂变为“已记分”，榜单数据即时刷新 | 自动选中下一场未完成对局。 |
| 输入非法比分 | 同分、胜方低于 11 分或差值小于 2 | 分数框与提示文字变砖红，解释具体原因 | 保留输入值，避免用户重复填写。 |
| 覆盖/清除赛果 | 点击覆盖保存或清除 | 弹出明确确认，成功后刷新全部统计 | 返回当前/下一场，不改变固定名单。 |
| 完赛颁奖 | 最后一场保存成功 | 赛事状态切换为“已完赛”，榜首卡强调冠军 | 颁奖页开放冠军、亚军、季军。 |

## 3. 页面状态

| 页面 | 空状态 | 进行中 | 完成状态 |
| --- | --- | --- | --- |
| 首页 | “首场待开球”，显示 0/15 | 显示下一场与已完成场数 | 显示冠军入口与 15/15。 |
| 赛程 | 全部卡片为“待开赛” | 已完成卡显示比分，下一场高亮 | 全部卡片显示最终比分。 |
| 榜单 | 所有人 0 积分，按固定顺序展示 | 以积分、净胜分实时排序 | 冠亚军行突出显示。 |
| 颁奖 | 提示尚余场次 | 显示“等待终局” | 呈现最终领奖台。 |

## 4. 响应式交互细则

桌面端把“赛程选择”和“录分”并排，便于场边快速切换。移动端将对局列表折叠为“选择对局”抽屉/横向带，分数输入放在上半屏；保存按钮保持固定在下方操作条，避免滚动后丢失。榜单在移动端将次要列折叠，点击单行后再查看得分和失分细节。所有卡片、标签和头像均必须包含文本名称，头像只做辅助识别。

## 5. 可用性与容错

系统不应静默纠正用户输入，也不应把非法比分写入本地存储。每个错误提示必须说明可执行的修正，例如“获胜方至少需要得到 11 分”或“获胜方需至少领先对手 2 分”。重置比分必须二次确认，并明确说明固定参赛名单不会被改动。
