# 小孩子作业记录网站 · 技术研发方案

| 项 | 内容 |
|---|---|
| 项目名称 | 小孩子作业记录网站（Homework Tracker） |
| 文档角色 | 全栈研发师产出 |
| 端组合 | Web（响应式，移动浏览器优先适配拍照场景） |
| 规模定位 | MVP，日活千级以内，单人/小团队可维护 |
| 下游交付 | 质量测试官、上线发布师、运维守护师 |

## 0. 上游对齐与冲突检查

- 端组合对齐：用户原始需求明确为"网站"，与平台选型结论（Web 单端）一致。不涉及 iOS/鸿蒙/小程序。
- 能力对齐：多小孩管理、账号体系、拍照识别、周/日/学科结构化记录，均为常规 Web + 第三方 AI API 可覆盖能力，不涉及实时音视频、支付、IM 等重型能力。
- 显式排除项（MVP 不做）：App 双端、微信小程序、支付/会员、实时音视频、多级缓存、微服务。
- 待确认假设：① 默认可使用 Vue 3 + TypeScript + Node.js（若只熟 React 可平替，架构不变）；② 有大陆云服务器与域名（ICP 备案 1~3 周，须与开发并行提交）；③ 第三方 AI 服务可正常开通。

## 1. 技术选型

### 1.1 选型结论

- 前端框架：**Vue 3 + Element Plus + TS**（选定——常规 Web 应用+轻后台，状态复杂度低，国内单人/小团队首选）；React + Ant Design 备选（团队只熟 React 时平替）；不选 SSR（无 SEO 诉求，过度设计）。
- 后端：**Node.js 20 + Express + TS + Prisma ORM + Zod + jsonwebtoken**（与前端同构 TS，全栈一人可 cover，IO 密集型匹配；重活外包给 LLM API）。
- 数据库：**MySQL 8.0**（选定；JSON 字段用 MySQL 8 原生 JSON 类型存识别结果；PostgreSQL 备选）。SQLite 禁用于多用户 Web 生产。
- 缓存/队列：**MVP 不引入** Redis/MQ（日活千级，JWT 无状态认证+内存限流+DB 状态机+进程内异步已足够）。
- 对象存储：**阿里云 OSS 私有 Bucket + CDN + STS 临时授权直传**（备选腾讯云 COS；降级服务端代理上传）。
- 识别：**阿里云百炼 Qwen-VL 多模态大模型（主）+ GPT-4o/Claude（备）+ 百度 OCR（降级）**。
- 监控：Sentry 免费档（前端 JS 错误）+ PM2 日志 + recognition_tasks 成本看板。

### 1.2 技术选型总表（端 × 层）

| 层 | 选定方案 | 理由 |
|---|---|---|
| 前端 Web | Vue 3.4 + TypeScript + Vite 5 + Element Plus + Pinia + Vue Router 4 + Axios | 国内 Web 首选，移动/桌面一套响应式代码 |
| 后端 | Node.js 20 LTS + Express 4 + TypeScript + Prisma + Zod + jsonwebtoken | 全栈一人可 cover；依赖少启动快 |
| 数据库 | MySQL 8.0 | 关系型作业记录标准选择，成本低 |
| 对象存储 | 阿里云 OSS 私有 Bucket + STS 直传 | 行业标准，按量付费，直传省带宽 |
| 识别服务 | Qwen-VL（主）+ GPT-4o/Claude（备）+ 百度 OCR（降级） | 手写体必须多模态；三级链路保证不中断 |
| 部署 | 单台云服务器 4C8G + Nginx + PM2（2 实例）+ Let's Encrypt | MVP 单机支撑 500 并发，运维动作最少 |

### 1.3 平替方案

- 团队只熟 React：前端换 React 18 + Ant Design + TS，目录与 API 契约不变。
- 已有腾讯云账号：OSS/COS 互换，Provider 抽象已隔离差异。
- 日活 >1 万：再评估 RDS 独立、Redis、模块化拆分。

## 2. 系统架构

### 2.1 部署拓扑

```
家长用户（手机/桌面浏览器）
   │ HTTPS（TLS 1.2+）
   ▼
CDN（静态资源；图片经签名 URL + OSS 图片处理参数取缩略图）
   ▼
Nginx（反向代理 + HTTPS 终止 + 静态资源 + 限流兜底）
   ▼
PM2 cluster（2 实例）── Node.js 应用（Express + TS）
   │                        ├── /api/v1/* REST API
   │                        ├── JWT 鉴权中间件 + 水平越权校验
   │                        └── 进程内异步任务（识别执行器，带超时与降级链）
   ├── MySQL 8（每日 mysqldump 全量备份 → OSS，保留 14 天）
   ├── 阿里云 OSS 私有 Bucket（作业照片，STS 直传，服务端签名 URL 读取）
   └── 第三方服务：Qwen-VL（主）/ GPT-4o/Claude（备）/ 百度 OCR（降级）/ Sentry
```

**MVP 明确不引入**：Redis、消息队列、K8s、读写分离、微服务网关。

### 2.2 核心请求链路

**链路 A：账号登录（JWT 双 Token）**：POST /auth/login（bcrypt 校验，失败限流 5 次/分/IP）→ 签发 access（2h）+ refresh（7d，哈希存表可吊销）→ 前端 Bearer 携带；过期用 refresh 静默续期；登出删 refresh 行。

**链路 B：拍照上传（移动浏览器 → OSS 直传）**：input capture 调起摄像头 → 客户端 canvas 压缩（长边 ≤1600px、JPEG 0.8、≤1MB）→ POST /upload/credential 签发 STS 临时凭证（权限限定 homework/{user_id}/* 前缀，15 分钟）→ ali-oss 直传 → 仅将 objectKey 提交服务端（**服务端只信任 objectKey，不信任客户端 URL**，防越权伪造）→ 携带 objectKey 创建/更新 homework（status=pending）。

**链路 C：智能识别**：POST /homeworks/{id}/recognize（状态机校验：仅 pending/recognize_failed 可触发；同 image_hash 已有成功结果直接复用）→ status=recognizing，写 recognition_tasks 审计行 → 从 OSS 拉取图片 base64 → Qwen-VL（25s 超时）→ 失败切备用 Provider → 再失败切百度 OCR → 成功：解析结构化 JSON，写 recognized_json + confidence，status=recognized → 前端渲染可编辑确认表单（低置信度高亮）→ 用户核对 → PUT /homeworks/{id} → status=confirmed → 全链路失败：status=recognize_failed，UI 提示手动录入（照片保留，功能不中断）。

**链路 D：周视图查询**：GET /homeworks/week-view?week_start=2025-03-10&child_id=1 → 服务端计算周一日期，一次查询返回 7 天 × N 学科结构化数据（避免 7×N 次请求）→ 命中索引 (child_id, week_start, weekday)，P95 ≤800ms。

### 2.3 反过度设计说明

| 被拒绝的设计 | 拒绝理由 |
|---|---|
| 微服务拆分 | 日活千级+单人维护，单体模块化即可 |
| Redis 缓存/会话 | JWT 无状态+MySQL 单机 QPS 足够 |
| 消息队列做识别 | 进程内异步+数据库状态机已满足 |
| K8s / 读写分离 | 单机 PM2 双实例支撑 500 并发 |

## 4. 拍照上传与作业识别技术方案（重点）

### 4.1 移动端拍照采集

- 控件：`<input type="file" accept="image/*" capture="environment">` 调起后置摄像头；同时提供"从相册选择"入口（不设 capture）。两入口共用同一压缩上传管线。
- 移动适配：viewport meta、touch-action 优化、按钮点击区 ≥44px、iOS Safari 安全区域 env(safe-area-inset)。
- 端差异：iOS Safari capture 受支持但不保证强制摄像头（符合预期）；Android Chrome 注意 EXIF 旋转（canvas 压缩按 image-orientation: from-image 处理）；相机权限被拒→降级相册+明确文案。

### 4.2 图片压缩与校验

- 客户端压缩：canvas 重绘，长边 ≤1600px（识别精度与成本平衡点），JPEG quality 0.8，目标 ≤1MB；同时省上传流量、省 LLM token、统一格式。
- 服务端校验（不信任客户端）：MIME 白名单（image/jpeg、png、webp）、大小 ≤5MB、魔数校验文件头。
- 存储规范：objectKey = homework/{user_id}/{child_id}/{yyyyMMdd}/{uuid}.jpg，STS 权限按前缀收紧，天然防跨用户写入。

### 4.3 上传通道（OSS 直传 + 回落）

申请 STS 临时凭证（15 分钟，限定前缀）→ ali-oss 直传 → 仅 objectKey 提交服务端绑定。回落：部分浏览器/网络直传失败率升高时切换服务端代理上传（POST /upload/proxy，multer 接收），带宽成本换可用性。

### 4.4 识别方案选型对比

| 方案 | 印刷体 | 手写体 | 成本 | 结论 |
|---|---|---|---|---|
| 云 OCR（百度/腾讯通用印刷体） | 好 | 差 | 低 | 降级链路 |
| 多模态大模型（Qwen-VL / GPT-4o / Claude） | 好 | **好** | 中（压缩图几分到几角/次） | **主链路**：作业场景手写为主 |
| 自研识别模型 | — | — | 极高 | 不选 |

结论：主链路 Qwen-VL（国内稳定、结构化输出可控），备用 GPT-4o/Claude，降级百度 OCR，最终兜底手动录入。Provider 抽象接口统一，配置化切换+失败自动降级。

### 4.5 识别流水线设计

结构化输出约定（Prompt 核心）：要求模型输出严格 JSON：

```json
{
  "overall_confidence": 0.92,
  "items": [
    { "subject": "数学", "content": "完成练习册第12页", "confidence": 0.95 },
    { "subject": "语文", "content": "背诵古诗两首并家长签字", "confidence": 0.88 }
  ]
}
```

Prompt 设计要点：system 定义"小学作业识别助手"角色与输出 schema；限定只输出 JSON 无解释文本；图片模糊/非作业图片时返回空 items + reason 字段（触发降级到手动）；prompt 版本号记入 recognition_tasks 便于回溯。

流水线状态机：

```
pending ──点击识别──▶ recognizing ──成功──▶ recognized ──用户确认/编辑──▶ confirmed
   ▲                      │
   │                      └──全链路失败──▶ recognize_failed ──重试/手动保存──▶ pending/confirmed
```

1. POST /homeworks/{id}/recognize：状态机校验；幂等（recognizing 中拒绝重复提交；同 image_hash 已有成功 task 直接复用，防重复计费）。
2. 置 recognizing，写 recognition_tasks（provider、model、prompt_version、image_hash）。
3. 拉取图片 → base64 内联（不经公网 URL，避免签名 URL 外泄与第三方缓存）。
4. 调用链：Qwen-VL（25s）→ 失败 GPT-4o（25s，若配置）→ 失败百度 OCR（10s，若配置）→ 全败 recognize_failed。每级失败记录 error_code。
5. 成功：解析并校验 JSON schema（Zod），写 recognized_json + confidence，status=recognized。
6. 前端展示可编辑确认表单；用户核对修改后 PUT 保存，status=confirmed。

超时与取消：前端识别等待上限 30s，提供"取消"（取消不影响服务端完成）；服务端每级超时后立即降级，不阻塞用户。

### 4.6 人工确认 + 手动编辑兜底（产品级闭环）

- 识别结果永远以"待确认草稿"呈现，UI 明示"识别结果仅供参考，请核对后再保存"。
- 每条结果可编辑（学科下拉+内容文本），低置信度条目（<0.7）黄色高亮置顶提醒。
- 用户可不识别直接手动录入（拍照仅作为附件存档）；识别失败时照片保留，表单为空待填。
- 检测到多学科内容时提示"可拆分多条记录"，MVP 先手动拆分。
- 所有路径终点明确：确认保存→confirmed；跳过→手动填写→confirmed；取消→保持 recognized/pending。

### 4.7 降级策略表

| 触发条件 | 自动动作 | 用户可见结果 |
|---|---|---|
| 主 LLM 超时/5xx（单次） | 切备用 LLM | 无感知 |
| 主+备 LLM 均失败 | 切百度 OCR（印刷体模式，学科需用户选择） | 提示"已切换基础识别模式" |
| OCR 也失败/图片不可读 | status=recognize_failed | 明确提示"识别失败，请手动输入"，照片保留 |
| LLM 连续 10 分钟失败率 >20% | 熔断标记，后续直接走 OCR | 提示基础识别模式 |
| 单用户识别 >10 次/小时 | 限流 429 | "识别太频繁，请稍后再试或手动录入" |
| 月识别成本超预算 200% | 人工调低模型档位/收紧限流 | 无感知 |

### 4.8 成本控制

客户端压缩到 ≤1MB 再送模型；识别按需触发不自动跑；同 image_hash 结果复用；recognition_tasks 记录每次调用的 provider/duration/confidence 形成成本与质量看板。

## 5. 数据模型设计

### 5.1 ER 关系

```
users 1──n children 1──n homeworks n──1 subjects（subjects.user_id 为 NULL 表示系统预设，全局共享只读）
users 1──n homeworks            （数据隔离以 user 为边界，所有查询强制 user_id 过滤）
homeworks 1──n recognition_tasks （识别审计流水）
users 1──n refresh_tokens
```

### 5.2 核心表字段

**users（用户/家长账号）**：id BIGINT PK；email VARCHAR(255) NULL UNIQUE；phone_ciphertext VARBINARY(512) NULL（AES-256-GCM 加密）；phone_hash CHAR(64) NULL UNIQUE（HMAC-SHA256，用于唯一校验与登录查找）；password_hash VARCHAR(255)（bcrypt cost=12）；nickname VARCHAR(50)；status TINYINT；last_login_at；created_at/updated_at/deleted_at。

**children（小孩档案）**：id；user_id NOT NULL；name VARCHAR(50)；grade VARCHAR(20) NULL；avatar_url/avatar_key；created_at/updated_at/deleted_at。索引 INDEX(user_id)、INDEX(user_id, deleted_at)。同名不在 DB 层建唯一约束（软删除后会阻碍重建），由服务层校验。

**subjects（学科）**：id；user_id NULL（NULL=系统预设全局共享只读；非空=用户自定义）；name VARCHAR(50)；sort_order；created_at/updated_at/deleted_at。种子数据：语文、数学、英语、科学、道德与法治、其他。

**homeworks（作业记录，核心表）**：id；user_id NOT NULL（数据隔离边界）；child_id NOT NULL；subject_id NOT NULL；week_start DATE NOT NULL（所属周周一，服务端统一计算 ISO 周）；weekday TINYINT NOT NULL（1=周一…7=周日）；content TEXT NULL；photo_key VARCHAR(255) NULL（OSS objectKey，私有）；recognized_json JSON NULL；confidence DECIMAL(4,3) NULL；source TINYINT（1=photo / 0=manual）；status TINYINT（0=pending 1=recognizing 2=recognized 3=recognize_failed 4=confirmed）；recognized_at；created_at/updated_at/deleted_at。索引 INDEX(user_id, week_start)、INDEX(child_id, week_start, weekday)、INDEX(user_id, status)、INDEX(user_id, created_at)。本项目无金额字段，不预留学生成/订单类字段。

**recognition_tasks（识别审计流水）**：id；homework_id/user_id；provider VARCHAR(32)（qwen/openai/claude/baidu_ocr）；model VARCHAR(64)；prompt_version VARCHAR(16)；status TINYINT（1=success 0=failed）；duration_ms INT；confidence DECIMAL(4,3) NULL；image_hash CHAR(64)（幂等复用键）；error_code/error_message；request_snapshot/response_snapshot JSON NULL（脱敏存档）；created_at。索引 INDEX(homework_id)、INDEX(user_id, created_at)、INDEX(image_hash)。

**refresh_tokens**：id；user_id；token_hash CHAR(64) UNIQUE（不存明文）；expires_at；created_at。

### 5.3 数据模型设计要点对照

| 参考文件要点 | 落实情况 |
|---|---|
| 时间戳三件套 | 全部业务表 created_at/updated_at，重要表 deleted_at 软删除 |
| 状态机字段 | homeworks.status 显式枚举+流转规则；recognition_tasks.status 成败记录 |
| 金额精度 | 本项目无金额，不引入浮点字段 |
| 扩展预留 | 仅对已明确方向预留（status 扩展位、prompt_version、image_hash） |
| 索引 | 按高频查询路径建索引，外键字段必建 |
| 冷热分离 | recognition_tasks 按月归档策略预留，首年不实施 |

## 6. API 设计

### 6.1 设计规范

RESTful 基线：资源名词复数+HTTP 动词；/api/v1 版本化。统一响应 { code, message, data, request_id }；code=0 成功；4xxx 客户端错误、5xxx 服务端错误，禁止 200 包一切。认证 JWT（access 2h + refresh 7d）。分页 page/pageSize（默认 20 上限 100）。写操作关键路径幂等。OpenAPI(Swagger) 随代码维护。

### 6.2 核心 API 清单

| 方法 | 路径 | 鉴权 | 幂等 | 说明 |
|---|---|---|---|---|
| POST | /api/v1/auth/register | 否 | 是（账号唯一） | 注册，限流 5 次/分/IP |
| POST | /api/v1/auth/login | 否 | 否 | 登录，限流 5 次/分/IP |
| POST | /api/v1/auth/refresh | Refresh | 是（轮换） | 刷新并吊销旧 refresh |
| POST | /api/v1/auth/logout | Access | 是 | 删除 refresh 行 |
| GET | /api/v1/auth/me | Access | 是 | 当前用户 |
| GET/POST | /api/v1/children | Access | 是 | 小孩列表/新增 |
| GET/PUT/DELETE | /api/v1/children/{id} | Access | 是 | 详情/更新/软删除 |
| GET/POST/DELETE | /api/v1/subjects（/{id}） | Access | 是 | 学科（系统预设禁删） |
| GET/POST | /api/v1/homeworks | Access | 是 | 列表（filter+分页）/手动新增 |
| GET/PUT/DELETE | /api/v1/homeworks/{id} | Access | 是 | 详情/更新（含识别确认保存）/软删除 |
| GET | /api/v1/homeworks/week-view | Access | 是 | 周视图：week_start+child_id→7 天结构化数据 |
| POST | /api/v1/homeworks/{id}/recognize | Access | **是**（状态机+image_hash） | 触发智能识别 |
| PUT | /api/v1/homeworks/{id}/photo | Access | 是 | 绑定/替换照片 objectKey |
| GET | /api/v1/homeworks/{id}/photo-url | Access | 是 | 签名访问 URL（15 分钟，带缩略图参数） |
| POST | /api/v1/upload/credential | Access | 是 | 签发 STS 临时凭证 |
| POST | /api/v1/upload/proxy | Access | 是 | 降级：服务端代理上传 |
| GET | /api/v1/stats/overview | Access | 是 | P1：本周作业数/待确认数 |

错误码分段：0 成功；1000 参数校验失败；1001 未登录/token 无效；1002 越权；1003 资源不存在；1004 频率限制；2001 账号或密码错误；2002 账号已存在；3001 识别服务暂不可用；3002 识别超时；3003 图片不可读；5000 服务端内部错误。

**水平越权校验（安全底线）**：所有带 id 的接口，服务层强制 AND user_id = 当前用户条件查询，命中不到一律返回 1003（不暴露资源存在性）。

## 7. 安全设计（儿童隐私数据保护为重点）

### 7.1 儿童隐私合规

- 主体关系：账号主体即家长/监护人，孩子数据由监护人本人录入与管理，符合"处理儿童个人信息应取得监护人同意"的立法本意；隐私政策明示数据用途。
- 数据最小化：仅收集手机号/邮箱+孩子称呼与年级+作业照片；不收集身份证号、学校名称、精确住址、精确生日。
- 照片保护：OSS 私有 Bucket（关闭公网读），读取一律服务端签名 URL（15 分钟有效，防盗链）；送 LLM 识别走 base64 内联不经公网 URL。
- 注销与删除：账号注销入口，注销后 30 天内删除个人数据（含照片 objectKey 物理删除），审计日志保留 ≥6 个月。
- 合规红线：识别结果 UI 常驻"仅供参考，请家长核对"提示。

### 7.2 认证与访问控制

密码 bcrypt(cost=12) 哈希；登录失败限流+通用错误文案（防账号枚举）；JWT 双 token；refresh 哈希入库可吊销；密钥仅存环境变量；全接口鉴权+水平越权校验；敏感操作（注销、删除孩子）二次确认。

### 7.3 传输/存储/输入/风控/审计

| 项 | 措施 |
|---|---|
| 传输 | 全站 HTTPS（TLS 1.2+），HSTS |
| 存储 | bcrypt 密码哈希；手机号 AES-256-GCM 加密+HMAC 索引 |
| 接口 | 鉴权全覆盖；资源归属校验；参数化查询（Prisma）防注入 |
| 输入 | Zod 全量参数校验；用户内容按纯文本处理（前端渲染转义） |
| 风控 | 登录/注册 5 次/分/IP；识别 10 次/小时/用户；全局 100 req/分/IP |
| 审计 | 登录日志、recognition_tasks 全量留存；关键操作日志 ≥6 个月 |
| 备份 | MySQL 每日 03:00 mysqldump 全量上传 OSS 保留 14 天；每季度恢复演练 |

## 8. 性能设计

- 图片链路：客户端压缩（≤1MB）→ OSS 直传 → 列表/详情用 OSS 图片处理参数生成缩略图（?x-oss-process=image/resize,w_400）→ 懒加载。
- 查询链路：周视图单次聚合查询命中索引；列表强制分页；Prisma 连接池 pool=10。
- 前端性能：Vite 构建+路由懒加载+gzip/brotli；静态资源走 CDN；首屏 FCP ≤2s（4G）。
- 识别链路：异步 UX，30s 前端上限+服务端分级超时；识别不计入核心 API P95。
- 容量基线：单机 4C8G+PM2 2 实例，目标 500 并发在线。

## 9. 多端适配说明

本期仅 Web 单端。浏览器兼容基线：Chrome/Edge/Safari 主流两版+iOS Safari/Android Chrome 近两大版本。响应式断点：移动优先 <768px 单列；768~1024px 两栏；>1024px 桌面三栏。移动拍照能力 input capture/accept 方案已显式处理端差异。iOS 审核/鸿蒙 ArkTS/小程序包体本期不涉及；V1.1 上小程序需提前配置域名白名单（备案+HTTPS）、主包 ≤2MB、订阅消息频次。
