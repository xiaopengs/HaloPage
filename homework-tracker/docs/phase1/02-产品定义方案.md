# 《小孩子作业记录网站》产品定义方案（含 PRD）

> 版本：V1.0 草案 | 角色：产品主理人 | 上游输入：用户原始需求 + 选型结论（响应式 Web，移动浏览器优先）
> 一致性声明：本方案严格基于上游选型结论"响应式 Web 网站"展开，未私自变更平台形态与目标用户。

## 一、产品定位与价值主张

| 维度 | 定义 |
|------|------|
| 产品定位 | 面向家长的多孩子作业结构化记录工具：拍照即记、AI 识别、按"每周→每天→学科"一屏掌握 |
| 价值主张 | 把"翻开孩子各科作业本逐本检查"的 10 分钟，压缩为"拍一张照、核对 3 秒、看板一屏览" |
| 目标用户 | 家长用户（妈妈/爸爸，一人管理 1~3 个孩子；家有小学生/初中生） |
| 核心场景 | 晚上孩子做完作业，家长用手机浏览器拍照上传 → AI 识别学科与内容 → 核对保存 → 周看板查看整周安排与完成情况 |
| 使用设备 | 手机浏览器为主（拍照场景），桌面浏览器为辅 |
| 差异化关键 | ①多孩子一键切换；②AI 识别 + 强制人工确认兜底（识别不准可改，绝不盲存）；③周视图日历式看板 |

**KANO 简化分类**：基本型（账号、多孩子档案、拍照上传、AI 识别、识别纠错、周看板）= MVP 必含；期望型（完成统计、学科自定义、图片重拍）= V1.0/V1.1；兴奋型（周报导出分享、每日提醒）= V1.2+；无差异（深色模式）= 推迟。

### 2.2 MVP 范围界定（V1.0）

- 纳入：F-01~F-09 全部 P0 + 默认学科预置（语文/数学/英语，F-10 的最小子集）。
- 不纳入：F-11~F-18 进 V1.1/V1.2+；不做支付、不做老师端、不做小程序/App。
- MVP 自检：功能点 9+1=10 个 ≤15 上限；识别走第三方服务不自研。

## 三、PRD（七章节标准模板）

### 1. 背景

家长每晚需逐一翻看孩子各科作业本了解作业量与完成情况，多孩家庭重复劳动翻倍；纸质登记和微信群消息易丢失、无法按周复盘。用"拍照+AI 识别+周看板"把这件事数字化、结构化。约束：备案周期（1~3 周）需与开发并行启动；AI 识别为第三方服务，存在准确率波动，必须以人工确认兜底。

### 2. 目标

| 项 | 内容 |
|----|------|
| 业务目标 | 上线首月：累计注册家长 ≥300；周活跃记录家长数（WAP）≥100；核心流程"注册→首条作业入库"转化率 ≥60% |
| 北极星指标 | **周活跃记录家长数（WAP）**：当周完成 ≥1 条作业记录的去重登录家长数 |
| 成功度量 | ①WAP 按埋点 homework_create 统计；②识别确认率 ≥70%，低于 55% 触发识别服务优化专项；③次周回访率 ≥30%；④P0 缺陷=0 |

### 5. 流程图说明（含异常分支，每步有出口）

**流程 A：注册/登录**：输入手机号（格式校验）→ 获取验证码（60s 倒计时）→ 校验通过：新手机号自动注册 → 写入协议同意记录 → 跳转来源页/首页。异常：格式错→按钮置灰+字段提示；网络失败→Toast+重试，不清空表单；60 秒内重复获取→置灰倒计时。

**流程 B：孩子档案创建与切换**：孩子切换器 → 管理孩子 → 添加 → 填姓名 → 保存 → 新孩子置顶+自动选中 → 看板刷新 → 空态引导。异常：姓名未填/超20字→置灰提示；删除孩子→二次确认明示级联删除；无孩子→空态+添加出口。

**流程 C：拍照上传 → AI 识别 → 确认入库（核心流程）**：看板"记作业" → 拍摄引导层（首次：平放/光线/完整入框）→ 调起相机（失败则相册入口常驻）→ 预览（重拍/使用）→ 上传压缩图 → 识别中（进度+文案，可取消）→ 识别结果确认页（学科下拉可改/日期可改/内容条目逐条可改可删可增，低置信度高亮）→ 点击"确认保存" → 入库 → 跳转作业详情。异常分支（关键兜底）：相机权限被拒→引导开启或相册选择，均不可用→手动录入；图片模糊/无文字→"未识别到作业内容"→重拍/手动录入；上传网络中断→本地保留草稿自动重试，3 次失败→手动录入；AI 服务超时/异常→转手动录入（图片保留为附件）；识别置信度低→黄色高亮"请核对"；学科无法判定→默认"未分类"高亮；连点提交→按钮防重+接口幂等。

**流程 D：周看板查看与管理**：登录后默认首页=本周看板（周一~周日 × 学科分组）→ 周切换（本周禁用"下一周"）→ 点击条目→作业详情。异常：本周无数据→空态+主按钮；历史周无数据→提示+返回本周；加载失败→错误态+重试。

**流程 E：完成状态标记与删除**：看板勾选/详情标记 → 即时反馈（卡片划线置灰、计数+1）→ 再次点击取消。删除：详情"删除"→二次确认（明示不可恢复）→ 删除成功 → 返回看板。异常：网络失败→状态回滚+失败提示+重试；取消删除→数据不动。

### 7. 验收标准

分功能验收（正常+异常均可测量，见用户故事表）；整体口径：核心流程 A~E 全通过（QA 用例通过率 100%）；P0 功能缺陷=0，P1 缺陷 ≤3 且无阻塞；埋点事件全部可上报；隐私政策/协议/备案齐全。

**不在本期范围（负向清单）**：第三方登录、支付订阅、小程序/App、老师端、AI 自动批改、语音输入、深色模式、多语言、数据导入、周报导出、消息推送、多家长共享、历史搜索。

## 五、多端体验规划

### 5.1 本期：响应式 Web（移动优先，桌面适配）

| 维度 | 移动端（<768px，主场景） | 桌面端（≥1024px，次场景） |
|------|--------------------------|--------------------------|
| 看板布局 | 单列按天分组，星期横向切换条 | 7 列周历网格 |
| 拍照 | 相机按钮直达，大点击区域 | 引导"发送链接到手机继续"或相册上传 |
| 交互 | 底部 Tab+大按钮、左滑条目出操作菜单 | hover 快捷操作、键盘 Enter 提交 |

### 5.2 拍照识别交互设计要点（产品关键兜底）

1. 拍摄引导：首次三步图文（平放/光线/单科单拍）；常驻取景框+四角对齐标记；示例照片对照。
2. 识别过程可见：进度动画+"约需 5-10 秒"，可取消（不丢图）。
3. 结果确认（强制人工把关）：结构化表单呈现，低置信度字段黄色高亮标注"请核对"；必须显式点击"确认保存"才入库，无自动盲存路径。
4. 纠错兜底：任意字段可手动修改；识别完全失败转手动录入且图片保留为附件；首次使用轻提示"AI 识别可能出错，保存前请核对"。
5. 数据反哺：埋点记录识别后是否编辑、编辑字段、确认耗时，形成"识别越用越准"迭代闭环。

### 5.3 后续端差异（V1.1+ 候选）

微信小程序（微信授权登录+订阅消息提醒）；App（Flutter/RN，厂商推送强召回）。能力降级预案：AI 失败→手动录入；相机权限拒→相册/手动；Web 无推送→短信/邮件。

## 七、需求变更管理

1. 任何新增/修改/删除记入需求池，标注提出人、日期、影响评估。
2. 区分"未开发"（直接调优先级）与"已开发/在开发"（评估返工量并给替代方案）。
3. 新需求默认进下一个版本；仅 P0 级闭环缺失或合规问题可插当前版本。
4. 影响工期或成本的变更须经用户确认后执行并记录。
5. 变更生效后同步研发/测试/上架材料。
6. 红线：禁止口头变更；禁止静默修改验收标准；累计变更致工期偏差 >30% 时重新评估整体计划。
