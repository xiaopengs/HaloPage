### 0.3 本阶段纪律声明（增长运营师专属红线）

1. **留存先于拉新**：本方案第二章（留存激活）完整回答"用户为什么来第二次"之前，第三章（获客）的任何预算建议均受"放量门禁"约束（见 2.7）——激活率 <60% 或次周回访率 <30% 时，禁止加大投放预算，预算保持在种子运营量级。
2. **指标必须有基线**：第一章所有核心指标均给出定义口径、埋点来源、目标值与基线取得方式（上线首周实测值即基线，之后按周滚动更新）；无基线的"提升活跃"类目标不进入周报。
3. **触达不骚扰**：邮件/短信/站内/小程序订阅消息全部设频率上限、免打扰时段与退订路径（见 2.4 频率红线表）；高频轰炸式策略禁止出现。
4. **流失必须可召回**：第五章给出流失定义、四层分层、每层召回渠道与话术、召回成本核算；只定义流失不做召回设计的条款不得入库。
5. **渠道可落地**：每个渠道均写明具体动作、频次、预算量级与预期新增量级（见第三章）；"全渠道铺开"式无优先级方案禁止输出。
6. **回访清单可操作**：第七章 48h/1 周回访清单全部为具体指标名称 + 测量方式 + 合格基线（数值化），空泛描述禁止出现。

## 二、留存激活设计（方案重点：先回答"用户为什么来第二次"）

> 本章先于获客投放设计。核心答案：**"每周一打开就能看到孩子们整周作业安排、拍一张照 3 秒完成记录、周日晚收到本周完成情况"** —— 产品挂到家长已有的"晚饭后检查作业"习惯上，用周看板 + 拍照省时 + 周报节拍构成回访理由。

### 2.1 新用户激活路径（≤3 步触达核心价值）

**设计原则**（对齐方法论 4.1）：缩短首次价值路径；空态不给白板；首次关键动作给即时反馈。

| 步骤 | 用户动作 | 产品承接（现状） | 增长补强动作 |
|---|---|---|---|
| 第 1 步 | 注册登录（账号密码，BQ-01） | 登录页 + 协议强制勾选（F-02） | 落地页/邀请页携带 utm_source；注册成功页直达引导，不落空白首页 |
| 第 2 步 | 添加第一个孩子（昵称 ≤20 字，无需真实姓名） | 孩子 Tab + 空态引导（TC-CHILD-006） | 空态三联引导：「添加第一个孩子」→「拍第一张作业」→「看看本周看板长什么样」，示例数据预览周看板（空态不给白板） |
| 第 3 步 | 拍一张作业照 → AI 识别 → 确认保存 | 拍摄引导层 + 识别确认页 + 周看板（F-04~F-08） | 首次拍摄引导层三步图文（平放/光线/单科单拍，产品已设计）；首次保存成功 = Aha 时刻强化（见 2.2） |

**激活转化目标**：注册 → 首条作业入库 **≥60%**（PRD 口径）；其中注册→添加孩子 ≥80%、添加孩子→首条作业 ≥75%。
**兜底原则**：激活路径任一步失败均有出口——相机权限拒→相册→手动录入；识别失败→手动录入（照片保留为附件）；上传失败→草稿自动重试 3 次→手动录入（技术方案降级策略表，闭环不断点）。

### 2.2 Aha 时刻设计（拍照识别省时体验）

| 项 | 设计 |
|---|---|
| Aha 时刻定义 | 家长拍一张作业通知照片 → 约 5-10 秒（BQ-03 口径）→ 系统自动填好学科与内容条目 → 核对 3 秒 → 确认保存 → 周看板立刻更新 |
| 时刻强化（保存成功页） | 「已为大宝记下 2 条作业」+「本周看板已更新」+ 首次成就徽章「第一张作业快照」；文案锚定价值主张：**"把逐本翻作业本的 10 分钟，压缩为拍一张照、核对 3 秒"** |
| 识别质量感知 | 识别结果强制人工确认（无自动盲存，US-06）；低置信度黄色高亮"请核对"——把"可控"做成信任感而非挫败感；UI 常驻"识别结果仅供参考，请家长核对"（技术方案 §7.1 合规红线） |
| 失败不破 Aha | 识别失败 → 照片保留 + 手动录入入口常驻，文案"识别没成功，照片已存好，手动录入一样快" |

### 2.3 留存策略（周报推送 / 习惯养成 / 家庭共享钩子）

#### 2.3.1 固定触发场景（习惯挂钩）

| 场景 | 时间 | 产品动作 |
|---|---|---|
| 晚饭后检查作业（挂到已有习惯） | 每日 19:00-21:00 | 看板默认首页 = 本周；「记作业」中央大按钮；晚间时段无推送打扰（免打扰） |
| 新一周开始 | 周一早 | 周看板自动切到新一周；上周未标记完成条目在周报中汇总提醒 |
| 周日晚复盘 | 周日 20:00 | 周报邮件/站内信送达（见 2.3.2） |

#### 2.3.2 周报推送（周期性回访节拍）

| 项 | 设计 |
|---|---|
| 形态 | **每周 1 封周报邮件**（V1.0 仅邮件+站内；V1.1 增加小程序订阅消息/短信） |
| 内容 | 只含**计数摘要**（"上周共记录 X 条、完成 Y 条、完成率 Z%"）+ 登录查看入口链接；**不含孩子姓名、作业明细、照片**（隐私边界见第八章） |
| 发送时间 | 每周一 08:00（家长通勤/上班前可看）或周日 20:00；二选一后固定，不随意变动 |
| 频率红线 | ≤1 封/周；退订入口在邮件底部 + 个人中心设置（≤2 步） |

#### 2.3.3 习惯养成与荣誉机制

| 机制 | 设计 | 说明 |
|---|---|---|
| 连续记录周数 | 看板展示"已连续记录 N 周"荣誉徽章 | 家庭工具不做断签惩罚/补签卡（避免焦虑感，家长对"打卡压力"敏感）；中断不清零，展示"最长连续 N 周" |

| 多孩子对比 | 切换孩子时展示各自本周完成率 | 多孩家庭核心价值感知点（产品差异化） |

#### 2.3.4 家庭共享钩子（留存 + 推荐双引擎，V1.1）

| 项 | 设计 |
|---|---|
| 钩子 | "邀请另一位家长一起记录"（妈妈记录、爸爸查看；或祖辈查看）——把单点使用变为家庭协作，提升留存与自然推荐 |
| 版本 | V1.1/V1.2 候选（F-16 多家长协作，产品定义 P2；技术方案 V1.2 family 表+权限模型） |

### 2.4 触达策略与频率红线表（Push/短信/邮件/站内）

> V1.0 现实约束：账号密码登录（BQ-01）、Web 端无推送能力 → **V1.0 触达通道 = 站内公告 + 邮件**；短信、小程序订阅消息为 V1.1 预留位（提前设好红线，上线即执行）。

| 通道 | 内容分级 | 频率上限 | 免打扰时段 | 退订/关闭路径 |
|---|---|---|---|---|
| 邮件-周报 | 个性化服务（事务性>个性化>活动） | **≤1 封/周** | 22:00-8:00 不发送 | 邮件底部退订链接（1 步）+ 个人中心通知设置（≤2 步） |
| 邮件-流失召回 | 个性化 | ≤1 封/2 周；同一分层连续召回 ≤3 次后停止转沉默 | 22:00-8:00 不发送 | 同上 |
| 站内公告 | 事务性（系统维护、识别服务波动） | 仅必要时；不承担营销触达 | 无（被动展示） | 公告可关闭 |
| 短信（V1.1 预留） | 事务性 + 重要召回 | ≤1 条/周；任何情况下每日 ≤1 条 | 22:00-8:00 禁止发送 | 回复 TD 退订 + 设置入口 |
| 小程序订阅消息（V1.1 预留） | 事务性（周报提醒/状态变更） | ≤1 条/周 + 即时状态 ≤1 条/日；遵守微信订阅消息规则（每次授权） | 22:00-8:00 不发送 | 小程序设置内关闭 |
| **全局红线** | — | **任何单通道每日 ≤1 条；家长可感知的营销触达每周 ≤3 条** | 22:00-8:00 | 所有触达可关闭，入口 ≤2 步 |

**内容分级纪律**：事务性（账号安全/系统维护）> 个性化（周报/孩子本周情况）> 活动推广；V1.0 无活动推广类触达。

### 2.5 会员与积分体系（V1.0 不做 + V1.2+ 预埋原则）

| 项 | 结论 |
|---|---|
| V1.0 | **不做积分/会员/打卡分享**——产品定义 KANO 已将"积分体系、打卡分享、社交动态"列入砍掉清单（家庭记录工具无社交场景）；运营侧不设任何积分钩子，避免与产品定义冲突 |
| V1.2+ 预埋原则 | 1) 先跑通单次价值再谈订阅：会员权益围绕"省时间/身份感"二选一（如多孩子上限、更长历史回看、周报长图导出模板）；2) 若做积分，必须"行为积分（周记录/反馈）+ 清晰价值出口（兑换权益）"双轨，不可兑换的积分等于空气；3) **防薅羊毛规则先于裂变活动上线**（单日上限、同设备判定）；4) 儿童隐私红线优先于任何会员设计——会员权益不得以"分享孩子数据"为条件 |

### 2.6 留存放量门禁（拉新预算的前置条件——本方案核心纪律）

| 门禁项 | 达标线 | 未达标时的动作 |
|---|---|---|
| 注册→首条作业入库转化率 | ≥60%（连续 2 周） | 预算锁死在种子运营量级（≤200 元/月）；全量投入修新手引导（漏斗 ③→⑦） |
| 次周回访率 | ≥30%（T+14 起按周统计） | 同上；触发留存实验而非加投 |
| 7 日留存曲线 | 走平或接近走平（周频工具以周为单位观察） | 未走平 = 瓶颈在激活/留存，**放大投放 = 漏桶注水，禁止** |
| 识别确认率 | ≥70%（且 >55% 红线） | 触发识别优化专项（6.4），不扩大曝光 |

## 五、流失预警与召回

### 5.1 流失定义与分层（按业务节奏：周频家庭工具）

| 层 | 定义 | 数据口径 |
|---|---|---|
| 新用户流失 | 注册后 7 天内未完成首条作业入库（未激活） | 注册 7 日内无 homework_create |
| 活跃用户衰退 | 已激活家长连续 2 个自然周 homework_create 条数环比下降 >50% | 周环比聚合 |
| 沉睡用户 | 连续 14 天未登录且无 homework_create | last_login_at + homework_create |
| 流失用户 | 连续 30 天未登录且无 homework_create（**流失定义期 = 30 天**，写入数据口径） | 同上 |

> 工具类产品按周节奏运营：14 天未活跃即进入沉睡干预，30 天未活跃判定流失；周一起算自然周，每周一 10:00 跑分层名单。

### 5.2 召回渠道与话术（分层策略）

| 分层 | 召回渠道 | 话术（身份认同 + 具体钩子 + 低门槛行动） | 激励 |
|---|---|---|---|
| 新用户流失（未激活） | 邮件（V1.1 起加短信） | 「您的作业看板还空着——3 分钟给大宝拍下第一条记录，这周安排一目了然」+ 新手三步引导直达链接 | 非物质：创始家长权益说明 |
| 活跃用户衰退 | 邮件 + 站内信 | 「本周看板已就绪，看看孩子们这周的安排；上周有 2 条还没标记完成」 | 连续记录周数荣誉恢复展示 |
| 沉睡用户（14-30 天） | 邮件 | 「您有 2 周没记录作业了。本周看板和周报已备好，点此 1 分钟回到节奏」 | 非物质；不发券（无营收产品禁补贴换活跃幻觉） |
| 流失用户（>30 天） | 邮件（最后 1 次触达） | 「账号和数据随时等您回来。孩子的历史记录都还在，登录即可查看」+ 数据保留与注销说明 | 无；此后转沉默，**仅停止营销触达，不删除任何数据**（注销才删，合规红线） |
| V1.1 起增补 | 短信（有手机号后）+ 小程序订阅消息 | 同上话术压缩为 60 字内；频次遵守 2.4 红线 | 同上 |

**召回承接纪律**：召回落地页直接到钩子内容（周报/看板），不落首页；召回用户 7 日内二次流失率纳入监控（对齐方法论 5.2）。

### 5.3 召回成本核算与实验

| 项 | 口径 | 目标 |
|---|---|---|
| 邮件成本 | 自建发信 ≈ 0.01-0.05 元/封 | V1.0 召回现金成本 ≈ 0 |
| 短信成本（V1.1） | ≈ 0.035 元/条 | 短信召回预算 ≤50 元/月 |
| 有效召回成本 | 召回总成本 ÷ 召回后 7 日内产生 ≥1 条 homework_create 的用户数 | ≤5 元/人 |
| 可持续性红线 | 召回成本 > 用户生命周期价值时停止加码激励 | V1.0 无营收，LTV 用"生命周期记录条数 × 单条节省时间价值"代理；**禁现金补贴换留存**（烧钱买留存幻觉反模式） |
| 召回实验 | A/B 激励力度（无激励 / 非物质荣誉 / 小额非现金权益），每月 1 轮，样本 ≥100 人/组 | 召回率提升 ≥20% 才全量 |

## 八、儿童隐私合规下的运营红线

> 依据：《个人信息保护法》第 31 条 + 《儿童个人信息网络保护规定》；选型报告 §4.4；技术方案 §7.1。运营侧红线如下，任何增长动作不得突破。

### 8.1 数据红线

1. **不向第三方共享儿童数据**：不接入任何采集儿童数据的第三方广告/统计 SDK；埋点事件仅含行为计数与时间戳，**不含孩子姓名、年级、作业内容、照片**；不与任何外部平台交换用户/儿童数据。
2. **监护人代理模式不可突破**：仅家长可注册，孩子档案由家长创建；运营动作（邀请、召回、共享）的对象只能是家长账号，不得诱导孩子注册或提供孩子信息。
3. **数据最小化**：运营素材与问卷不得收集孩子真实姓名、学校、生日、住址；孩子档案只用昵称（大宝/二宝）。
4. **删除权**：账号注销后 30 天内删除个人数据（含照片 objectKey 物理删除）；运营侧每月核对注销工单闭环；召回触达对象如已注销，立即从所有名单移除。

### 8.2 营销内容边界

1. **素材边界**：所有对外素材（小红书笔记、海报、台卡、落地页截图）一律使用示意图或脱敏造数；**禁止使用真实儿童的作业照片、面部、姓名做营销素材**；家长在社群自发晒图的，运营引导其打码，不转载未打码内容。
2. **触达内容边界**：邮件/短信/订阅消息内容只含家长本人账号的计数摘要，不含孩子姓名与作业明细（详见 2.3.2）；分享卡片只分享产品本身，不分享含作业内容的页面（技术层无社交分享功能，产品定义已砍）。
3. **话术边界**：不使用"让孩子赢在起跑线"类焦虑营销；不使用儿童形象代言；不承诺"识别 100% 准确"（识别为辅助，人工确认兜底是产品红线）。
4. **广告/变现红线**：V1.0 起不在站内接入任何广告；未来商业化不得以儿童数据为变现标的。

### 8.3 增长活动禁令清单

| 禁止项 | 原因 |
|---|---|
| 晒娃打卡/作业分享裂变 | 产品定义 KANO 砍掉"打卡分享、社交动态"；儿童隐私高风险 |
| 要求提供孩子信息才能参与的邀请活动 | 数据最小化红线；邀请只针对家长账号 |
| 现金补贴换注册/活跃 | 无营收阶段烧钱买留存幻觉；补贴停止即归零 |
| 购买第三方"家长名单"进行外呼/群发 | 数据来源合法性红线 |
| 高频短信/邮件轰炸 | 触达频率红线（2.4） |
| 分享链接携带用户/儿童数据参数 | 越权与泄露风险；链接只带 UTM 渠道参数 |

## 九、增长实验计划

### 9.1 首个实验假设与判定标准

| 项 | 内容 |
|---|---|
| 实验名称 | 新手三联引导对激活率的提升 |
| 假设 | **如果**在新用户注册后的看板空态页增加「添加第一个孩子 → 拍第一张作业 → 预览示例周看板」三联引导（并在上传成功后即时展示"本周看板已更新"成就反馈），**则**注册→首条作业入库转化率从首周基线提升至 ≥60%，**因为**首次价值路径从"注册后面对空白首页"缩短为 3 步直达核心价值，且保存成功即时强化了"省时"的 Aha 感知 |
| 变量 | 单变量：空态三联引导 + 保存成功成就反馈（对照组 = 现有空态） |
| 样本与时长 | 冷启动期用户量小，采用**时间段轮换对比**：周一至周三实验组、周四至周日对照组，滚动 2 周，每组 ≥50 个注册（不足则延长至样本达标） |
| 判定标准 | 实验组转化率 ≥60% 且高于对照组 ≥10 个百分点 → 全量；无差异 → 记录关闭；显著下降 → 回滚并复盘 |
| 台账 | 实验（含失败）记入实验台账：假设/分组/样本/结果/决策/日期，避免重复踩坑 |

### 9.2 实验纪律

1. 假设驱动、单变量、明确样本与周期、四象限决策（显著提升→全量 / 无差异→记录关闭 / 显著下降→回滚复盘 / 样本不足→延期不决策）；
2. 每周实验 ≤2 个并行（小团队产能约束）；
3. 所有实验不得触碰第八章合规红线与 2.4 触达红线；
4. 实验涉及容量的（如邀请裂变），提前过 3.4 容量闸门。
