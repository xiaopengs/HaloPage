### 1.4 测试环境与数据策略

| 项 | 策略 |
|---|---|
| 环境分层 | ① 本地开发环境（Docker MySQL，自测）；② 测试环境（staging：类生产配置，独立域名+HTTPS，OSS 独立 Bucket，AI Provider 接测试 Key 或 Mock）；③ 生产环境仅做 UAT 后验收抽测与灰度观察 |
| 测试账号 | 家长账号 ≥5 个（含 1 个三孩账号、1 个空数据新账号）；管理员账号 1 个；每个账号预置不同孩子数与作业量 |
| 造数策略 | 预置真实量级数据：孩子档案 ≥10、作业记录 ≥5000 条、跨 ≥8 个自然周、含软删除与 recognize_failed 状态数据；**空库测出的性能是假象，性能测试必须在造数后执行** |
| 识别测试集 | 收集 ≥30 张真实场景照片（印刷体通知/手写作业本/潦草字迹/斜拍逆光/非作业无关图各若干），作为识别完整率 ≥80% 验收基准集，纳入版本回归 |
| 手机号/隐私 | 测试数据一律脱敏；禁止在生产库直接构造测试数据；儿童信息最小化（仅昵称+年级） |
| 第三方 Mock | AI Provider（Qwen-VL/GPT/百度 OCR）提供 Mock 开关，用于异常流与降级链路的可重复验证；真实链路每周至少 1 次全真调用 |

### 1.5 测试节奏与准入准出标准

1. **提测准入（冒烟）**：研发提测前须自测通过冒烟集（五条核心流程正常流）；QA 冒烟 1 个工作日内完成，任一核心流程跑不通直接打回，不进入全量测试；
2. **全量功能测试**：P0 用例 100% 执行，P1 用例按风险抽查，P2 用例本轮不执行（登记）；
3. **回归测试**：每个 bug 修复后 24h 内回归验证；上线前执行全量核心回归集；
4. **UAT 验收**：按 PRD §7 验收标准由产品主理人/种子用户确认；
5. **准出**：达到第九章质量门禁全部量化项，方可出具放行结论交上线发布师。

## 三、核心测试用例集

### 3.0 用例统计与设计方法

- 设计方法：等价类划分（合法/非法手机号、图片格式）、边界值（0/1/最大值：孩子姓名 0 与 20 字、图片 5MB、验证码 60s、限流 5 次/分）、场景法（五条核心业务链路）、状态迁移（homeworks.status 状态机：pending→recognizing→recognized/recognize_failed→confirmed 逐跳验证）。
- **用例统计：正常流 21 条，异常流 30 条（异常/正常 ≈ 1.43 ≥ 0.5，满足异常流覆盖红线）**；另含管理后台 3 条。
- 用例模板字段：用例编号 / 模块 / 标题 / 优先级 / 前置条件 / 步骤 / 预期结果 / PRD 追溯。

## 八、缺陷管理流程

### 8.1 Bug 报告规范（七要素，缺项视为无效报告）

| 字段 | 要求 |
|---|---|
| 标题 | `[模块] 现象 + 条件`，一句话可定位，如：`[拍照上传] iOS Safari 相机权限拒绝后无相册降级入口` |
| 严重级别 | **P0 致命**（白屏/崩溃/数据丢失/主流程阻断/儿童数据泄露）、**P1 严重**（主要功能错误、核心验收不达标、严重体验问题）、**P2 一般**（次要功能异常）、**P3 轻微**（文案/样式） |
| 环境 | 设备型号、系统版本、浏览器及版本、前端版本号/构建号、账号（脱敏）、网络状态（WiFi/4G/3G/断网） |
| 复现步骤 | 编号步骤，他人按步骤必须能复现；无法稳定复现的标注概率（如"3/10 次"）与环境 |
| 实际结果 vs 预期结果 | 分开写，预期结果必须引用 PRD 验收标准或技术承诺值 |
| 证据 | 截图/录屏/Sentry 链接/请求响应报文（HAR），三要素缺一不收 |
| 复现概率 | 必现 / 高频（>50%）/ 偶现（注明次数比例） |

### 8.2 流转流程

`新 Bug → 确认（可复现/有效，24h 内）→ 修复 → 回归验证（修复后 24h 内）→ 关闭`；偶现 bug 附日志并跟踪至概率归零或给出根因说明；P0/P1 bug 每日站会过清单；bug 关闭权在 QA，研发自关无效。

### 8.3 缺陷趋势反哺

每日输出缺陷趋势（新增/修复/存量按级别）；识别相关缺陷聚类反哺 prompt 与样本回归集；上线后缺陷与埋点（ocr_fail、manual_entry_use）交叉分析，反哺研发与产品。
