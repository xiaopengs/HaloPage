## 一、项目概述与三要素

| 要素 | 结论 |
|------|------|
| **做什么系统** | 小孩子作业记录网站（Web，移动端优先） |
| **面向谁** | 家长用户（核心画像：一二线城市 30-45 岁家长，1-2 个孩子，愿意为"省时间"的工具付费/持续使用） |
| **核心目标** | 拍照上传作业 → AI 识别成结构化条目 → 按周/日/学科归档跟进，降低家长手工记录负担 |
| **平台选型** | 响应式 Web 网站 + 同站 Web 管理后台（不单独做 App/小程序） |
| **MVP 范围** | P0 功能 9 项（F-01~F-09），P0 占比 50%（未超 60% 红线） |

**需求本质判断**（选品洞察师结论）：本质是"信息录入工具 + 结构化档案"，不是社交、不是内容平台。核心竞争力在**录入体验**（拍照 → 识别 → 确认，三步完成）与**结构化展示**（周看板一眼看清一周各科作业分布）。家长是"操盘手"角色，孩子档案是"被记录对象"。

## 二、Phase 1 立项与定义（三份方案摘要）

完整原文见 `docs/phase1/` 下三份文档。三份方案结论经团长核对**互相不矛盾**：平台形态（响应式 Web）、MVP 范围（P0=9 项）、技术栈（Vue3 + Node/Express + SQL 类数据库）三要素一致。

### 2.1 选品洞察师 → 《需求与平台选型报告》

- **KANO 分类**：基本型（账号/多孩档案/拍照上传/AI 识别/周看板）= MVP 必含；期望型（完成统计/学科自定义）= V1.1；兴奋型（周报分享/每日提醒）= V1.2+；无差异（深色模式）= 推迟。
- **平台选型**：七平台对比矩阵 + 决策树推导 → **响应式 Web**（理由：开发成本最低、无商店审核、家长移动浏览器即用即走、后续可平滑扩展小程序）。
- **可行性四维度**：技术可行（VL 大模型 API 成熟）、市场可行（家长工具类需求稳定存在）、合规可行（需儿童个人信息保护规则+隐私政策）、投入可行（MVP 单人 4-6 周）。
- **风险预警**：识别准确率不及预期（→ 人工确认兜底 + 手动录入降级链）；儿童个人信息合规（→ 隐私政策专章 + 最小化采集）。

### 2.2 产品主理人 → 《产品定义方案（含 PRD）》

- **产品定位**："3 步记完一周作业"——拍（拍照/相册）→ 认（AI 识别成条目）→ 看（周看板跟进）。
- **PRD 七章节**：产品概述 / 用户与场景 / 功能清单（18 项：P0×9 / P1×6 / P2×3）/ 用户流程（主流程 6 步 + 异常分支）/ 信息架构 / 非功能需求 / 埋点与数据。
- **核心用户流程**：注册 → 建档（孩子+学科）→ 拍照上传 → AI 识别 → 人工确认/修改 → 周看板展示 → 每日勾选完成。
- **状态机**：PENDING → RECOGNIZING → RECOGNIZED/RECOGNIZE_FAILED → CONFIRMED（**识别结果绝不自动盲存，必须人工确认**）。
- **埋点表**：注册完成率、建档完成率、拍照→识别转化、识别成功率、识别→确认转化、周看板回访率（已全部落实到运营阶段）。

### 2.3 全栈研发师 → 《技术研发方案》

- **技术选型**：前端 Vue 3 + Vite + Element Plus + Pinia；后端 Node.js + Express + SQL 数据库；识别层 DashScope（Qwen-VL，OpenAI 兼容端点）。
- **系统架构**：SPA → API 网关（JWT 双 Token）→ 业务路由 → 数据层；识别层 Provider 抽象 + 降级链。
- **非功能承诺**：识别主链路单次 ≤10s（总上限 30s）；上传图片压缩统一 ≤1MB；水平越权零容忍（所有带 id 查询强制 user_id 校验）；密码 bcrypt 加密。
- **安全设计**：JWT access 2h + refresh 7d（哈希入库、轮换）；登录限流；上传 MIME 白名单 + 魔数校验；照片读取登录态 + 归属校验。

## 五、Phase 4 运维保障（摘要）

完整原文见 `docs/phase4/01-运维保障方案.md`。

- **监控告警体系**：健康检查 `/api/v1/health`（60s 间隔）；核心指标（可用性/识别成功率/P95 延迟/错误率）；告警阈值表（P0 立即电话 / P1 30min 内 / P2 工单）。
- **SLO/SLA**：可用性 99.9%；识别成功率 ≥90%（无 Key 环境下降级手动录入不计入）；核心接口 P95 ≤500ms。
- **应急预案**：识别服务故障 → 自动降级手动录入（**闭环不断点是验收红线**）；数据库故障 → 每日备份恢复；磁盘满 → uploads 清理策略 + 告警。
- **成本优化**：单机部署月成本基线（约 ¥150-300）；识别调用按量计费预估（日均 100 次识别 ≈ ¥2-5/月）。

## 六、Phase 5 增长运营（摘要）

完整原文见 `docs/phase5/01-运营增长方案.md`。

- **北极星指标**：周活跃记录家庭数（每周有 ≥3 天有点击/记录行为的家庭）。

- **数据指标基线**：注册→建档转化 ≥60%；拍照→识别转化 ≥70%；识别→确认转化 ≥80%；次周回访率 ≥30%（V1.0 基线，上线后实测校准）。
- **数据复盘节奏**：上线后 48h 看稳定性指标；上线后 1 周看留存与漏斗，输出 v2 迭代建议。

### 7.4 技术实现亮点

1. **零原生依赖数据库**：采用 Node 22 内置 `node:sqlite`（DatabaseSync），规避 better-sqlite3 二进制兼容问题，`npm install` 无需编译，**换机部署零障碍**。
2. **识别 Provider 抽象 + 降级链**：`recognition.js` 统一 Provider 接口，链路 qwen → openai_compat → 手动兜底，**闭环不断点**（任一环失败用户都能完成记录，这是 Phase 2 定的验收红线）。
3. **JWT 双 Token 安全体系**：access 2h + refresh 7d；refresh 哈希入库、轮换、jti 随机因子防重放；前端 axios 拦截器 401 自动刷新重试（去重队列）。
4. **移动端录入体验**：相机直调 + canvas 压缩 + 自动上传 + 自动识别 + 确认表单，家长操作步数最少化（拍 1 次 → 确认 1 次 → 完成）。
5. **运维内建**：每日 VACUUM INTO 自动备份（保留 14 天）；结构化审计流水（识别 provider/耗时/置信度全记录）；health 端点。

## 八、方案与落地差异说明

《技术研发方案》面向生产环境给出理想选型，本 MVP 在沙盒环境交付时做了如下**向后兼容的务实替换**（生产扩容路径不受影响，详见 `app/README.md`）：

| 项 | 技术研发方案 | MVP 落地 | 替换理由与影响 |
|----|--------------|----------|----------------|
| 数据库 | MySQL 8 | `node:sqlite`（WAL 模式） | 沙盒零外部依赖、一键启动；SQL 语法兼容，数据模型不变；日备份机制已内建。生产扩容：改 `db.js` 连接串即可（模型已按标准 SQL 设计） |
| 图片存储 | 阿里云 OSS | 本地 `uploads/` 目录 | MVP 阶段省去 OSS 配置与费用；`routes-upload.js` 存储层已抽象（photo_key 与 OSS object key 同构），换 OSS 只改存储实现 |
| 后端语言 | TypeScript | JavaScript（ESM 风格 CommonJS） | 减少构建链复杂度，交付即运行；模块边界清晰（config/db/util/auth/recognition/routes-*），后续可渐进加 TS |
| 识别主链路 | 百度 OCR → VL 模型 | 直接 Qwen-VL（DashScope）→ OpenAI 兼容端点 → 手动兜底 | OCR 版式方案对"作业拍照"场景泛化差，VL 多模态直接理解图文更准；降级链反而更短更稳 |
| 部署 | Nginx + PM2 双实例 | 单端口 Node 服务 | 沙盒交付形态；接口与 SPA fallback 已按生产标准实现，前置 Nginx 即可升级 |
| 账号体系 | 账号密码 + 短信（规划） | 账号密码（BQ-01 裁决） | 按团长裁决口径执行，短信登录留 V1.1 |

> 以上差异均已通过团长核对，不影响 Phase 2~5 各方案的非功能性承诺（越权防护、备份、降级链、监控口径全部落实）。

## 十、上线运行信息

- **访问方式**：单端口 Node 服务，API 与前端同源部署（`/api/v1/*` + 静态资源 + SPA fallback）。
- **公网分享链接**：私有部署，访问地址与 sharecode 不在仓库公开。
- **健康检查**：`GET /api/v1/health` → `{"code":0,"message":"ok","data":{"ts":...}}`。
- **本地/内网启动**：

### 10.1 公网部署关键发现：边缘代理覆盖 Authorization 头

实测发现平台公网边缘代理会**覆盖标准 `Authorization` 请求头**（平台网关行为），导致 JWT 无法经标准头送达。处置方案（已落地并全量验证）：服务端 `extractToken()` 三通道提取——`X-Auth-Token` 自定义头（主力，穿透率 100%）→ `?token=` 查询参数（供 `<img>` 照片场景）→ `Authorization`（本地标准场景）；前端 API 客户端与照片 URL 已同步适配。详见 `app/README.md`「鉴权 Token 传输通道」。

### 10.2 V1.1 视觉重构（2026-10-25 已上线）

- 前端全量重构为“作业夹”设计系统：移除 Element Plus，重建 7 个页面、设计令牌与原生组件；桌面看板两列、移动端日期锚点布局。
- 手动录入升级为主路径：大输入框每行一条，实时计数，选择孩子/日期/学科后批量保存；新增 `POST /homeworks/batch` 事务接口，旧服务端自动降级逐条保存。
- 公网生产构建实测：9 项核心流程全通过、JS 错误 0；主包由 872KB 降至约 200KB（gzip 约 80KB）。
